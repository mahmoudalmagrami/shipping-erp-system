# نظام إدارة الشحن والترحيل المالي (Shipping & Financial Posting ERP)

نظام سحابي متكامل لإدارة شركات ووكالات الشحن والخدمات اللوجستية وفق معايير هندسة البرمجيات النظيفة (Clean Architecture) والدورة المحاسبية للقيد المزدوج الصارم (Strict Double-Entry Bookkeeping).

---

## 🏗️ 1. المعمارية الهندسية والأنماط (Architecture & Design Patterns)

تم بناء المشروع باتباع أفضل ممارسات هندسة النظم المؤسسية:
* **Clean Architecture & Domain-Driven Design (DDD Lite):**
  - **طبقة النطاق (Domain Layer):** عزل الكيانات وحساب الأوزان (`PricingCalculator`) والمحرك المالي (`AccountingEngine`) عن أطر العمل الخارجية.
  - **طبقة حالات الاستخدام (Use Cases):** (`CreateInitialOrderUseCase`, `DispatchToFinalUseCase`, `CalculateRateUseCase`, `GetFinancialSummaryUseCase`).
  - **طبقة الوصول للبيانات (Repositories & DB Adapter):** قاعدة بيانات سريعة وآمنة ومبنية على معايير ACID ووضع الـ WAL لحفظ وتتبع كافة الحركات.
  - **طبقة التقديم والواجهات (Presentation & Web API):** خادم REST API وواجهة مستخدم تفاعلية متطورة تدعم اللغة العربية واتجاه اليمين لليسار (RTL).

---

## 🔒 2. معايير الأمان والرقابة المالية (Security & Integrity)

1. **سلامة القيود المحاسبية (Double-Entry Invariant):**
   - التحقق البرمجي التام من تساوي المدين والدائن ($\sum \text{Debits} = \sum \text{Credits}$) قبل تنفيذ أي حركة في قاعدة البيانات.
2. **المعاملات الذرية (ACID Transactions):**
   - جميع عمليات إنشاء الشحنات وحركات الصندوق وترحيل الموردين محاطة بـ `BEGIN TRANSACTION` و `COMMIT` لضمان عدم حدوث أي قيد معلق في حال حدوث خطأ.
3. **حماية التكرار والبوالص (Idempotency & Uniqueness):**
   - أرقام الطلبات الأولية فريدة ومستقلة (`ORD-2026-XXXXX`).
   - بوالص الموردين مشروطة بعدم التكرار على مستوى قاعدة البيانات (`supplier_waybill_number UNIQUE`).
   - منع إعادة ترحيل الشحنة لأكثر من مرة أو التلاعب بها بعد الترحيل.
4. **التحقق وتطهير المدخلات (Strict Validation):**
   - استخدام مكتبة `Zod` للتحقق الصارم من صحة الأوزان، الأبعاد، أرقام الهواتف، وأسماء العملاء والموردين.
5. **حماية الهجمات السيبرانية:**
   - تطبيق `Helmet` و `CORS` لحماية ترويسات HTTP ومنع الاستعلامات الخبيثة (Prepared Statements ضد هجمات SQL Injection).

## 🔄 3. دورة العمل والأثر المالي (Business Workflow)

### المرحلة 1: الطلب الأولي (Initial Order Booking)
- إدخال بيانات المرسل، المستلم، الوزن الفعلي والحجمي، ومنطقة الوجهة (الخليج، أوروبا، أمريكا، آسيا...).
- **التأثير المالي الفوري:**
  - إذا كان الدفع **نقداً:** يزيد رصيد **الصندوق** (مدين) + تزيد **المبيعات** (دائن).
  - إذا كان **صراف / بنك:** يزيد رصيد **حساب الصراف** (مدين) + تزيد **المبيعات** (دائن).
  - إذا كان **آجل:** تثبت مديونية على **حساب العميل** (مدين) + تزيد **المبيعات** (دائن).

### المرحلة 2: محطة الترحيل للنهائي (Final Carrier Dispatch)
- يتم استيراد الطلب الأولي بنقرة واحدة (دون إعادة كتابة أي بيانات).
- اختيار الناقل/المورد (مثل: DHL, Aramex, FedEx, أو ناقل خاص).
- إدخال **رقم بوليصة المورد الصادرة منه**.
- تحديد تكلفة الشحن المستحقة للمورد.
- **التأثير المالي الفوري:**
  - إثبات استحقاق مالي للمورد: **حساب المورد دائن** + **تكلفة مبيعات الشحن مدين**.
  - احتساب صافي هامش الربح المحقق تلقائياً:
    $$\text{Net Profit} = \text{سعر بيع الطلب الأولي} - \text{تكلفة بوليصة المورد}$$

## 🚀 4. تشغيل النظام محلياً (How to Run)

1. **تشغيل الخادم:**
   ```bash
   npm start
   ```
2. **فتح لوحة التحكم في المتصفح:**
   افتح الرابط التالي:
   [http://localhost:3000](http://localhost:3000)

3. **تشغيل الاختبارات الآلية:**
   ```bash
   node test-integration.js
   ```

## 📡 5. وثائق الـ APIs الرئيسية

| الطريقة | المسار | الوصف |
| :--- | :--- | :--- |
| `POST` | `/api/orders` | إنشاء وحفظ طلب أولي جديد مع القيد المحاسبي الفوري |
| `GET` | `/api/orders` | استعراض كافة الشحنات مع الفلترة والبحث |
| `GET` | `/api/orders/pending-dispatch` | استعراض الطلبات الأولية المعلقة بالمستودع بانتظار الترحيل |
| `POST` | `/api/dispatch` | ترحيل الطلب الأولي لنهائي برقم بوليصة المورد وتكلفته |
| `GET` | `/api/pricing/zones` | جلب مصفوفة الوجهات والشرائح والأسعار |
| `POST` | `/api/pricing/calculate` | حاسبة فورية لحساب الوزن الحجمي والمفوتر والسعر |
| `GET` | `/api/accounting/summary` | ملخص الأرصدة اللحظية (الصندوق، الصراف، الموردين، الأرباح، والقيود) |
